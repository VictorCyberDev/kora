### What the live run found (and fixed)

Running the second incident on a site whose only published version was the failing one showed a real defect: Kora correctly proposed only a read-only health check (there is no earlier version to restore), but the owner status said **Checking recovery** while the latest observation was still HTTP 500. Fixed in PR #19 (`cb871bf`): a read-only re-check never advances owner status; a regression test fails without the fix. The authoritative run above is on the fixed build. The earlier run on `fab20e3` (incident `8d294a6c-395c-48bb-ae39-167a1466fec0`, also verified `PASS`) is kept as [`acceptance-run1-fab20e3.evidence.json`](docs/live/acceptance-run1-fab20e3.evidence.json) for transparency.
